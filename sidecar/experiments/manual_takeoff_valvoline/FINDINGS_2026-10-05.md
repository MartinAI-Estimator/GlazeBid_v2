# Valvoline manual takeoff — findings for auto-takeoff
*2026-10-05 · Blind takeoff by Claude on the 75-sheet "Original Drawings" set, then compared with Martin's marked set (19 sheets, 50 markups). Artifact: "Valvoline Fountain Takeoff".*

## Result
- **18 of 18** scope objects Martin marked were found blind: SF-A, SF-B, SF-C, SF-D; doors D2, D3, D9; glazing-only lites D5, D8; hardware H1/H2; sill flashing; 11 of 12 detail/section titles; Bobrick mirror excluded.
- **0** false scope.
- Sizes from snapping to vector lines matched Martin's Bluebeam Areas within ½" (A: 10'-8.4" × 10'-0" vs his 10'-8⅜" × 9'-11 15/16").
- Misses: detail title 1/A-6.2 (threshold), the two scope-note blocks on A-6.1, the "2 Thus" at door type C. One position error (SF-B plan box 40 pt west of the wall).
- Extras of mine, defensible: jamb break metal (2, 3/A-6.2), double alum head filler (5/A-6.2), red exclusions on OH doors / awnings / HM doors (Martin leaves those blank).
- Box-for-box agreement with his 50 markups: 57%. Nearly all of the gap is convention (he marks tag boxes and frame-type labels; I marked openings and schedule rows).

## How it was actually done (the method that worked)
1. **Sheet index from the cover** (text layer) → 19 A-sheets out of 75. Text search for storefront / glass / mirror / skylight across the other 56 sheets confirmed nothing hidden in C/S/M/P/E.
2. **Schedules first (A-6.1).** The Storefront Opening Schedule gave marks A–D, W×H, frame type, series (Kawneer 451T), details. The Door Schedule's MATERIAL column (AL/GL, HM/GL, HM) sorted every door into ours / glazing-only / not ours. Door types A–E drawings settled which lites are glass.
3. **Floor plan tag search.** `search_for("D2")` etc. found every tag once; the dimension strings on the same wall gave the opening extents. The plan count was the truth, exactly as Martin said.
4. **Elevation snap.** Vector lines inside a window around each opening → outer frame = W×H, mullion spacing = bays/rows. No vision model needed on vector PDFs.
5. **Details by title + keywords.** "BREAK METAL TO MATCH STOREFRONT", "PROVIDE DBL. ALUM. FRAME", "ALUMINUM SILL FLASHING" located by text search, classified by Martin's rules.
6. **Trade rules decided every in/out call** (OH lites out, HM lites glazing-only, Bobrick out, awning brake metal matches EIFS → out).

## Bugs and gaps found in the current GlazeBid code
- **Rotated pages.** 18 of 19 A-sheets are stored rotated 90°. PyMuPDF `search_for()` and `get_drawings()` return UNROTATED coordinates; `get_pixmap(clip=)` and the corpus annotation rects are in ROTATED coordinates. `geometry_anchoring.py` never multiplies by `page.rotation_matrix`, so every tag→box snap on a rotated sheet lands in the wrong place. One-line fix per call site. Likely a big part of the July precision numbers.
- **The scorer compares rectangles, not scope.** A correct takeoff drawn in a different convention scores 57%. Score by scope object: found / classified / counted / sized.
- **Schedule-first is not how the pipeline runs.** Legend → elevations → schedules. On this set the schedule is the whole key.
- **Tag search is cheaper and more exact than vision for counting.** Vision is only needed when tags are images (scans) or absent.
